# План реализации: локальный самообучаемый ИИ-агент (Windows, .exe)

## 1. Цель и трактовка требований

Итоговый продукт — desktop-приложение под Windows (`.exe`), которое:

- работает **локально** (не веб-сервис), запускается двойным кликом;
- ведёт диалог и **выполняет задачи** (агентный цикл "думать → действовать → проверять");
- **самообучается**: накапливает память о прошлых задачах, успешных/неуспешных попытках и постепенно расширяет набор своих навыков (skills/tools) — без полного переобучения весов модели (это нереалистично на обычном ПК, см. раздел 8);
- имеет **систему запретов/разрешений**: пользователь может ограничить доступ к файлам, командам, сайтам, типам действий;
- умеет **создавать документы и презентации** (Word, PowerPoint, PDF, Excel);
- имеет **доступ в интернет** для поиска информации и **новых инструментов/навыков**, которые не хватает для решения задачи;
- собирается в единый `.exe`-файл (или инсталлятор).

Важное уточнение по терминам: "самообучение" в реалистичном виде — это не дообучение нейросети на лету (это дорого, нестабильно и не нужно для 95% задач), а **накопление опыта**: долговременная память + библиотека навыков + анализ обратной связи. Это стандартный подход в современных агентных системах (в том числе в Claude Code / Claude Agent SDK), и он даёт наблюдаемый эффект "агент становится лучше со временем" без переобучения модели.

## 3. Технологический стек

| Компонент | Выбор | Почему |
|---|---|---|
| Язык ядра | **Python 3.11+** | Вся ML/агентная экосистема, `python-docx`, `python-pptx`, `playwright` и т.д. |
| Desktop GUI | **PySide6 (Qt)** | Нативный вид под Windows, один рантайм (без связки Python+Electron через порт/IPC), стабильная упаковка в exe |
| Агентный цикл | Собственный orchestrator поверх **Claude Agent SDK** (или LangGraph как альтернатива) | Готовый цикл tool-use, стриминг, управление контекстом |
| LLM | **Claude API** (по умолчанию) + опционально **локальная модель через Ollama/llama.cpp** (офлайн-режим) | Баланс качества (облако) и приватности/офлайна (локально) |
| Долговременная память | **SQLite** (структурированная история) + **ChromaDB/FAISS** (векторный поиск по опыту) — всё локально, файлы на диске | Не требует внешней БД, работает offline |
| Генерация документов | `python-docx`, `python-pptx`, `reportlab`/`weasyprint` (PDF), `openpyxl` | Стандартные библиотеки, локальная генерация без внешних сервисов |
| Веб-доступ | HTTP через `httpx` + поиск через API (Brave Search/Bing) + `Playwright` для сценариев, где нужен браузер | Разделение "быстрый поиск" и "тяжёлый браузинг" |
| Sandboxing/permissions | Собственный **Policy Engine** (allow/deny списки, перехват каждого вызова инструмента) | Аналог permission-системы Claude Code — прозрачно и проверяемо |
| Установка новых навыков | Изолированное `venv` для `pip install` + реестр MCP-совместимых инструментов | Не засоряет основное окружение, откатываемо |
| Упаковка в .exe | **PyInstaller** (`--onefile`) или **Nuitka** (компиляция в машинный код, быстрее и компактнее) + **Inno Setup** для инсталлятора | Стандартный путь Python → Windows exe |

## 4. Ключевые модули подробно

### 4.1 Agent Core (Orchestrator)
- Цикл: **Planner → Executor → Critic/Reflector**.
- Planner разбивает задачу на шаги, Executor вызывает нужные инструменты, Critic проверяет результат и решает: повторить, скорректировать план или завершить.
- После завершения задачи — этап **рефлексии**: что сработало, что нет, какие новые навыки понадобились → запись в память.

### 4.2 Память и самообучение
- **Краткосрочная память**: контекст текущего диалога/задачи.
- **Долговременная память**: векторная БД с эпизодами (`задача → план → результат → оценка`). Перед новой задачей агент делает retrieval похожих прошлых случаев (RAG) — это и есть механизм "обучения на опыте".
- **Библиотека навыков**: каждый успешно опробованный инструмент/скрипт/промпт-паттерн сохраняется как переиспользуемый "skill" (по аналогии с Skills в Claude) с описанием, когда его применять.
- **Обратная связь пользователя**: явные оценки ("хорошо/плохо", правки) тоже пишутся в память и влияют на будущий выбор стратегии.

### 4.3 Policy / Permission Engine (запреты)
- Конфигурируемые правила на уровне: файловые пути (allow/deny), сетевые домены, типы действий (запуск команд, установка пакетов, отправка данных наружу), лимиты (время, объём).
- Каждый вызов инструмента идёт через Policy Engine **до** выполнения; опасные операции требуют явного подтверждения пользователя в UI (как permission-prompt).
- Настройки хранятся в локальном конфиге (`policy.yaml`), редактируются через вкладку "Права доступа" в UI.
- Полный аудит-лог всех действий агента (для прозрачности и отладки).

### 4.4 Документы и презентации
- Единый модуль `DocumentSkills`: `create_docx`, `create_pptx`, `create_pdf`, `create_xlsx`, с шаблонами (титульный слайд, таблицы, диаграммы через `matplotlib`/встроенные средства pptx).
- Агент вызывает эти функции как обычные инструменты (tool calls), результат — файл на диске, который открывается пользователю.

### 4.5 Интернет-доступ и приобретение новых навыков
- Обычный поиск: search API → сводка результатов.
- Если для задачи не хватает инструмента — агент:
  1. ищет решение (библиотека/API/CLI-утилита);
  2. **запрашивает разрешение** у пользователя на установку (через Policy Engine, если пакет/домен не в allow-list);
  3. устанавливает в изолированное окружение;
  4. тестирует на простом примере;
  5. при успехе регистрирует как новый skill в библиотеке навыков (постоянно, для будущих задач).
- Это и есть контролируемый механизм "самообучения новым инструментам", безопасный за счёт пункта 2.

### 4.6 UI
- Вкладки: **Чат/задачи**, **Права доступа**, **Библиотека навыков** (что агент уже умеет), **Память/история**, **Настройки** (API-ключи, локальная/облачная модель).

## 5. Этапы реализации (дорожная карта)

**Этап 0 — Каркас (1–2 недели)**
- Repo setup, базовый Agent Core с одним LLM-провайдером и одним инструментом (эхо/файловые операции).
- Простой Qt-интерфейс с чатом.

**Этап 1 — Права доступа и базовые инструменты**
- Policy Engine + UI настроек прав.
- Файловые операции, выполнение shell-команд с sandbox и подтверждением.

**Этап 2 — Документы и презентации**
- Модуль генерации docx/pptx/pdf/xlsx, интеграция как tool calls.

**Этап 3 — Память и самообучение**
- SQLite + векторная БД, запись эпизодов, retrieval перед планированием, рефлексия после задачи.

**Этап 4 — Интернет и приобретение навыков**
- Поиск в интернете, Playwright-браузинг, механизм автоматической установки/регистрации новых skills с разрешениями.

**Этап 5 — Упаковка**
- PyInstaller/Nuitka → `.exe`, инсталлятор Inno Setup, автообновление (опционально, через проверку версии на GitHub Releases).

**Этап 6 — Полировка**
- Офлайн-режим (локальная модель через Ollama), логи/аудит, тесты, документация пользователя.

## 7. Риски и ограничения

- **Размер exe**: Python + ML-зависимости (embeddings, playwright) дают файл от ~150 МБ до 1+ ГБ — это ожидаемо для такого класса приложений, не баг упаковки.
- **Автономная установка пакетов/выполнение кода** — главный источник риска; обязательна изоляция (venv/контейнер) и явное подтверждение пользователя для всего, что выходит за пределы allow-list.
- **"Настоящее" самообучение (дообучение весов)** на потребительском ПК нецелесообразно — заменяется памятью+RAG+библиотекой навыков, что и является отраслевым стандартом для таких агентов.
- **Зависимость от облачного LLM** для лучшего качества рассуждений; офлайн-режим с локальной моделью будет заметно слабее в сложном планировании.
- **Антивирусы** часто ложно триггерятся на PyInstaller-exe — потребуется подписание кода (code signing certificate) для доверенного распространения.

## 8. Итог

Реалистичный путь: Python-ядро агента (планирование + инструменты + память + политика доступа) с Qt-интерфейсом, упакованное в `.exe` через PyInstaller/Nuitka. "Самообучение" реализуется через накопление опыта (векторная память + рефлексия) и растущую библиотеку навыков, а не через дообучение модели. Доступ в интернет и установка новых инструментов всегда проходят через Policy Engine с подтверждением пользователя — это делает агента одновременно расширяемым и безопасным.
