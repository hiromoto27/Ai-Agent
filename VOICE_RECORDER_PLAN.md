# План реализации: нейросетевой диктофон с протоколами задач

> **Статус: MVP реализован** (см. вкладку «Диктофон» в GUI и раздел
> [«Диктофон»](README.md#диктофон) в README) — политика доступа к
> микрофону, хранилище (`ai_agent/core/voice/store.py`), самообучаемый
> классификатор задач (`classifier.py`), захват звука и локальный STT
> (`audio.py`/`stt.py`, требуют `extras: voice`), протоколы и напоминания.
> Не проверено на реальном микрофоне (нет аудиоустройства в песочнице
> сборки) — см. «Известные ограничения» в README. Ниже — исходный план и
> обоснование архитектурных решений.
>
> Дополнение к [`PLAN.md`](PLAN.md) — не отдельный проект, а новый модуль
> существующего локального агента (`ai_agent/`). Переиспользует Policy
> Engine, `MemoryStore`, реестр навыков (`Skill`) и Qt-интерфейс, а не
> создаёт параллельную инфраструктуру.

## 1. Цель и трактовка требований

Модуль «Диктофон», встроенный в приложение:

- слушает микрофон **по запросу** (разовая запись, явное действие
  пользователя) **и** может быть переключён в режим **постоянной
  записи** (слушает фоном, пока пользователь сам не выключит);
- распознаёт речь **локально** (без отправки аудио в облако по
  умолчанию — см. раздел 4.2);
- ведёт диалог: если непонятно, к чему относится сказанное, **задаёт
  уточняющий вопрос**, а не гадает — так же, как уже делает основной
  агент (`DEFAULT_SYSTEM_PROMPT` в `orchestrator.py`);
- превращает распознанный разговор в **протокол**, разбитый по
  задачам (task 1: пункты A, B…; task 2: пункты C…);
- **понимает, к какой задаче относится фрагмент разговора**, по
  контекстным словам, и **самообучается**: каждое подтверждение или
  отклонение пользователя ("да, это к задаче X" / "нет, не туда")
  повышает точность будущей классификации для этой задачи;
- **напоминает** о задачах (по сроку/условию), используя те же
  задачи, что видны в протоколах.

Термин "самообучаемая модель" здесь трактуется так же, как и в
основном `PLAN.md` (раздел 8): не дообучение весов нейросети "на
лету" (нереалистично локально и не нужно для этой задачи), а
**онлайн-обучаемый классификатор на контекстных словах** —
по задаче накапливается взвешенный профиль ключевых слов, который
корректируется каждым подтверждением/отклонением пользователя. Это
наблюдаемое "агент становится точнее со временем" без переобучения
STT-модели или LLM.

## 3. Технологический стек (новое)

| Компонент | Выбор | Почему |
|---|---|---|
| Захват аудио с микрофона | **`sounddevice`** (обвязка над PortAudio) | Готовые wheels под Windows/Linux/macOS, не требует компилятора — важно для упаковки в `.exe`, как и остальной проект |
| Детектор речи (VAD) | **`webrtcvad`** | Лёгкий (C-расширение без ML-весов), делит непрерывный поток на реплики/паузы — нужен именно для режима постоянной записи |
| Локальное распознавание речи (STT) | **`faster-whisper`** (CTranslate2, модели `tiny`/`base`/`small`/`medium`) как основной вариант; **`vosk`** — ультралёгкий офлайн-фолбэк для слабых ПК | `faster-whisper` даёт заметно лучшее качество для русской речи и пунктуацию; выбор конкретного размера модели — через уже существующий `autotune.Profile` (как выбор LLM-модели сейчас) |
| Классификация по задачам | Собственный **контекстный классификатор** (bag-of-words + TF-подобные веса на задачу, без torch) | Прямое расширение уже написанного `_tokenize`/`_cosine_similarity` в `memory/store.py` — тот же подход, что и для retrieval эпизодов, без новых тяжёлых зависимостей |
| Уточнение/суммаризация протокола | Существующий `LLMProvider` (Claude API / локальная GGUF-модель / LM Studio) | Из расшифровки + меток задач формирует связный текст протокола и выделяет пункты-действия; при отсутствии LLM (тестовый режим) — эвристика по ключевым глаголам ("нужно", "сделать", "до <дата>") |
| Протокол как документ | Существующий `DocumentSkills.create_docx` | Не новый модуль — просто новый шаблон "протокол по задачам" |
| Напоминания | Фоновый **`QTimer`** в GUI (при запущенном приложении) + системные уведомления через `QSystemTrayIcon.showMessage` (уже есть Qt) | Без новых тяжёлых зависимостей типа APScheduler; ограничение — приложение должно быть запущено (см. раздел 7) |
| Упаковка | Добавляется extra `voice` в `pyproject.toml`: `sounddevice`, `webrtcvad`, `faster-whisper` (+ `vosk` опционально) | Модели STT (как и LLM-модели сейчас) не входят в `.exe` — скачиваются/импортируются через тот же механизм, что и вкладка «Модели» |

## 4. Ключевые модули подробно

### 4.1 Доступ к микрофону: по запросу vs. постоянно

Новая секция в `policy.yaml` (по аналогии с `model_download`/`shell`):

```yaml
microphone:
  enabled: false            # разовая запись — выключена по умолчанию
  continuous_enabled: false # отдельный, более строгий флаг для фонового режима
  retain_audio: false       # хранить ли WAV-файлы после расшифровки (по умолчанию — только текст)
```

- Разовая запись (`voice.start_recording`) — обычное разрешение
  `microphone.enabled`, как остальные навыки: включил один раз в
  настройках — дальше работает без переспроса на каждый вызов.
- Постоянная запись (`voice.start_continuous`) — **отдельный** флаг
  `microphone.continuous_enabled` в `confirmation_required_for`:
  подтверждение запрашивается **каждый раз** при включении режима
  (не при каждой фразе), потому что риск отличается качественно —
  агент слышит всё, что происходит рядом, а не только явно
  надиктованное.
- Пока постоянная запись активна — обязательный постоянный визуальный
  индикатор (иконка в трее меняет цвет/анимируется + строка в UI
  «🔴 Идёт запись»), чтобы это никогда не происходило незаметно для
  самого пользователя.
- По умолчанию сохраняется **только текст расшифровки**, не сами
  аудиофайлы (`retain_audio: false`) — меньше приватных данных на
  диске; хранение WAV — отдельная опция для тех, кому нужна аудио-
  верификация протокола.

### 4.2 Локальное распознавание речи

- `AudioCapture`: поток с микрофона через `sounddevice` → кольцевой
  буфер → `webrtcvad` режет его на реплики (речь/тишина), а не
  подаёт в STT всё подряд — экономит ресурсы в режиме постоянной
  записи и не пытается "распознать" тишину или фоновый шум.
- Каждая обнаруженная реплика уходит в очередь на распознавание,
  обрабатывается `faster-whisper` в фоновом потоке (не блокирует
  UI/остальную работу агента) — как уже сделано для выполнения задач
  через `ui/worker.py`.
- Модель STT выбирается по `autotune.Profile`, как сейчас выбираются
  рекомендуемые LLM-модели на вкладке «Модели»: слабый ПК → `tiny`/
  `base`/Vosk, мощный → `small`/`medium`.
- Облачная альтернатива (например, Whisper через API) — не
  обязательна, но может быть добавлена как ещё один провайдер, по
  той же схеме, что и провайдеры LLM ("локально/облачно" — выбор
  пользователя, не жёстко зашитый путь).

### 4.3 Классификатор задач и самообучение (ядро фичи)

Структура данных на задачу — `TaskProfile`:

```python
@dataclass
class TaskProfile:
    task_id: int
    positive_words: Counter[str]   # веса слов "за" эту задачу
    negative_words: Counter[str]   # веса слов "против" (были в отклонённых фрагментах)
    confirmations: int = 0
    rejections: int = 0
```

Алгоритм для каждой новой распознанной реплики/группы реплик:

1. Токенизация текста тем же `_tokenize`, что и в `memory/store.py`.
2. Косинусное сходство реплики с `positive_words` каждой активной
   задачи, минус штраф за пересечение с `negative_words` —
   получаем рейтинг задач-кандидатов.
3. Если лучший кандидат явно впереди второго (порог разрыва,
   настраиваемый) — **автоматически** помечаем реплику этой задачей
   и **тихо** обновляем её `positive_words` (усиление без вопроса,
   чтобы не задёргивать пользователя на каждой явной фразе).
4. Если разрыв мал / уверенность ниже порога / реплика не похожа ни
   на одну активную задачу — **уточняющий вопрос** в UI (и в чате):
   *«Отнести фрагмент "…" к задаче "Согласовать бюджет"?»* — 
   Да / Нет / Другая задача / Новая задача.
5. Ответ пользователя — обучающий сигнал:
   - «Да» → слова реплики усиливают `positive_words` этой задачи
     (`confirmations += 1`), а не подошедших кандидатов — слегка
     ослабляют её `negative_words` не трогаем, но снижаем их
     будущий приоритет по этой реплике.
   - «Нет» → слова уходят в `negative_words` отклонённой задачи-
     кандидата (`rejections += 1`), классификатор в следующий раз
     будет меньше её предлагать для похожего текста.
   - «Другая задача» → те же обновления, но к выбранной задаче.
   - «Новая задача» → создаётся `TaskProfile` с нуля из текста этой
     реплики (пользователь задаёт название).
6. Порог "автоматически / уточнить" сам подстраивается: чем больше
   `confirmations` у задачи, тем увереннее классификатор её
   предлагает без вопроса — это и есть измеримый рост "уровня"
   (доли автоматических, не переспрошенных классификаций), который
   просил пользователь.

Это прямое расширение уже реализованного в проекте принципа
"самообучение = накопление опыта + retrieval", просто на уровне
слов конкретной задачи, а не эпизодов агента в целом. Веса
профилей задач сохраняются в SQLite — переживают перезапуск
приложения.

### 4.4 Протокол по задачам

- Навык `voice.generate_protocol(session_id)`: берёт все реплики
  сессии (или диапазон времени для постоянной записи), группирует
  по назначенной задаче, прогоняет через `LLMProvider` (если
  настроен) для связного пересказа + выделения пунктов-действий на
  задачу, иначе — эвристика по ключевым словам ("нужно", "сделать",
  "к <дата>", "договорились").
- Результат — новый шаблон в `DocumentSkills`: `create_meeting_protocol`
  (`.docx`), заголовки — задачи, под каждой — пункты с таймкодом
  и (опционально) прямой цитатой из расшифровки для проверяемости.
- Нераспределённые реплики (ни одна задача не подошла и пользователь
  не уточнил) идут в раздел "Не отнесено" — ничего не теряется
  молча.

### 4.5 Напоминания по задачам

- Расширение модели задачи: `due_at`, `reminder_rule` (за N часов до
  срока / по условию, например "когда откроется следующий разговор
  по этой задаче").
- `ReminderScheduler` — фоновый `QTimer` в GUI-процессе проверяет
  просроченные/приближающиеся напоминания и показывает системное
  уведомление + сообщение в чате агента ("Напоминаю: «Согласовать
  бюджет» — срок сегодня").
- Ограничение по-честному: работает, пока приложение запущено (как
  и постоянная запись) — это desktop-приложение, а не сервис;
  фиксируется в разделе рисков, а не скрывается.

### 4.6 UI

Новая вкладка **«Диктофон»**:
- Кнопка разовой записи + переключатель постоянной записи с ярким
  индикатором состояния.
- Живая лента расшифровки (реплика за репликой, с меткой задачи,
  если уже определена).
- Блок уточняющих вопросов по классификации (Да/Нет/Другая/Новая).
- Список задач с профилем уверенности классификатора и кнопкой
  "Сформировать протокол".
- Панель напоминаний (создать/отредактировать срок для задачи).

## 5. Хранение данных (расширение схемы)

Новые таблицы в `~/.ai-agent/memory.sqlite3` (тот же файл, что и
`episodes`, — не отдельная БД):

```
recordings(id, started_at, ended_at, mode)              -- разовая/постоянная
utterances(id, recording_id, ts, text, task_id NULL)    -- реплика + результат классификации
tasks(id, title, description, due_at, reminder_rule, created_at)
task_profiles(task_id, positive_words JSON, negative_words JSON, confirmations, rejections)
reminders(id, task_id, fire_at, fired BOOLEAN)
```

Аудиофайлы (если `retain_audio: true`) — в
`~/AiAgentWorkspace/recordings/`, рядом с уже существующими
`documents/`/`scripts/`/`models/`.

## 6. Этапы реализации (дорожная карта)

**Этап 0 — Захват звука**
- `AudioCapture` + `webrtcvad`, разовая запись → WAV в памяти,
  без STT — проверить, что микрофон вообще пишет корректно на
  целевых ОС.

**Этап 1 — Локальный STT + Policy**
- Интеграция `faster-whisper` (+ выбор размера модели по
  `autotune.Profile`), навыки `voice.start_recording`/`stop`,
  секция `microphone.*` в `policy.yaml`, подтверждения в UI.

**Этап 2 — Модель задач и классификатор**
- Таблицы `tasks`/`task_profiles`/`utterances`, `TaskClassifier`
  (раздел 4.3), UI уточняющих вопросов, ручное создание задач.

**Этап 3 — Протоколы**
- `voice.generate_protocol` + шаблон `create_meeting_protocol` в
  `DocumentSkills`, вывод в `.docx`.

**Этап 4 — Постоянная запись**
- Фоновый режим (`voice.start_continuous`), непрерывная сегментация
  через VAD, обязательный индикатор записи, отдельное подтверждение
  политики.

**Этап 5 — Напоминания**
- `due_at`/`reminder_rule` у задач, `ReminderScheduler`, системные
  уведомления.

**Этап 6 — Полировка и упаковка**
- Extra `voice` в `pyproject.toml`, обновление `packaging/build.spec`
  (включить/протестировать бинарники `sounddevice`/`webrtcvad`/
  `ctranslate2` в PyInstaller), тесты (юнит на классификатор —
  детерминированный и не требует реального микрофона/модели в CI),
  документация в README (по аналогии с разделом про LLM-провайдеров).

## 7. Риски и ограничения

- **Запись третьих лиц**: постоянная запись микрофона может писать
  голоса людей, не давших согласия, — юридически это регулируется
  по-разному в разных юрисдикциях (во многих требуется согласие всех
  участников разговора). Это ответственность пользователя
  приложения, но продукт обязан: (а) не включать эту функцию по
  умолчанию, (б) держать явный и постоянный визуальный индикатор
  активной записи, (в) не отправлять аудио никуда по умолчанию
  (см. `retain_audio`/локальный STT). Стоит явно показать
  предупреждение при первом включении постоянного режима.
- **Точность STT на русском/смешанной речи, акцентах, наложении
  голосов** — реалистичный whisper-класса движок ошибается заметно
  чаще на плохом микрофоне/шуме; протокол не должен подаваться как
  дословная стенограмма без возможности сверки (отсюда — таймкоды и
  цитаты в протоколе, раздел 4.4).
- **Холодный старт классификатора**: пока у задачи мало
  подтверждений, точность низкая и уточняющих вопросов будет много —
  это ожидаемо и подсвечивается в UI как "уровень уверенности", а не
  скрывается.
- **Ресурсы на слабом ПК**: STT + VAD в реальном времени при
  постоянной записи заметно грузят CPU — обязательно завязывать
  размер модели на существующий `autotune.Profile`, не только для
  LLM.
- **Диск при `retain_audio: true`**: непрерывная запись быстро
  накапливает гигабайты — нужен лимит хранения/ротация, если эта
  опция включена.
- **Напоминания работают, только пока приложение открыто** — это
  desktop-инструмент без фонового сервиса/автозапуска; если нужна
  надёжная доставка напоминаний при закрытом приложении, это отдельная
  и более сложная задача (системная служба/автозапуск), не входит в
  этот план.

---

## 8. Итог

Модуль пристраивается к уже существующему агенту, а не строится с
нуля: захват аудио и STT — новые, но лёгкие локальные зависимости
(без torch/облака по умолчанию); классификация задач и "самообучение"
— прямое расширение уже реализованного в `MemoryStore` подхода
"bag-of-words + накопление обратной связи"; протоколы используют
готовый `DocumentSkills`; права на микрофон идут через тот же Policy
Engine, что и остальные потенциально чувствительные действия, с
дополнительным более строгим контуром для постоянной записи и
обязательным индикатором активности.
