# AI-Agent

Локальный самообучаемый ИИ-агент: работает на ПК пользователя, имеет
систему прав доступа (запретов), умеет создавать документы и
презентации, пишет себе вспомогательные скрипты, ходит в интернет за
информацией и новыми навыками, и автоматически подстраивается под
мощность текущего компьютера. Архитектура и обоснование решений — в
[`PLAN.md`](PLAN.md).

## Быстрый старт (разработка)

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -e ".[all]"
pytest -q                          # 100+ тестов, должны все проходить
```

### CLI

```bash
python -m ai_agent.cli                          # интерактивный режим
python -m ai_agent.cli --once "Создай заметку"   # одна задача, для скриптов/CI
```

Без `ANTHROPIC_API_KEY` в окружении и без выбранной локальной модели
агент работает на офлайн-заглушке (`EchoProvider`, буквально повторяет
вопрос) — полезно для тестов и разработки без сети, но это **не
настоящий ИИ**. Настройте провайдер (см. раздел ниже) — через
переменную окружения `ANTHROPIC_API_KEY` или прямо в приложении, на
вкладке «Настройки».

### GUI (Qt-приложение)

```bash
python -m ai_agent.ui.app
```

Тёмная тема, чат в виде сообщений-пузырей, вкладки с иконками: **Чат**
(диалог с агентом, с сохранением истории в рамках сессии), **Настройки**
(выбор провайдера/модели, системный промпт — см. ниже), **Модели**
(подбор и скачивание LLM с Hugging Face под характеристики вашего ПК),
**Навыки** (что агент умеет), **Память** (история задач и статистика
успехов — механизм самообучения), **Права доступа** (текущая политика).

## LLM: выбор провайдера, модель, системный промпт

По умолчанию агент отвечал эхом просто потому, что не был настроен
реальный источник ответов — на вкладке **Настройки** это решается:

- **Провайдер** — выпадающий список: *Автоматически* (облако, если
  задан ключ, иначе локальная модель, если указана, иначе тест),
  *Claude API*, *Локальная модель (GGUF)*, *Тестовый режим*. Наверху —
  строка «Сейчас отвечает: …», всегда показывающая, что реально
  используется прямо сейчас.
- **Claude API** — поле для `ANTHROPIC_API_KEY` (можно оставить пустым
  и задать переменной окружения) и название модели.
- **Локальная модель** — выпадающий список `.gguf`-файлов, найденных в
  `workspace/models` (то, что вы скачали или импортировали на вкладке
  «Модели»), с кнопкой обновить. Требует отдельно поставленный пакет
  `llama-cpp-python` — **не входит** в обычную установку `[all]`,
  потому что на большинстве систем у него нет готового wheel на PyPI и
  он собирается из исходников (нужен компилятор C++). Поставить:
  `pip install "ai-agent[local-llm]"`. Это экспериментальный путь:
  вместо "нативного" function calling используется текстовый протокол
  (`TOOL_CALL: <навык> <JSON>`), который работает с любой
  инструкт-моделью, но соблюдается тем надёжнее, чем крупнее модель —
  мелкие квантованные модели (0.5–1.5B) могут путать формат чаще, чем
  Claude или модели покрупнее.
- **Системный промпт** — свободный текст поверх базовых инструкций
  агента: стиль ответов, роль ("ты — ассистент по Python…"),
  ограничения. Например: «Отвечай только на русском и кратко».

Явно выбранный провайдер (не «Автоматически») **не деградирует молча**:
если он не смог запуститься (нет ключа/пакета/файла модели), приложение
не падает — оно остаётся в тестовом режиме, но статус на вкладке прямо
покажет причину, а не тихо продолжит отвечать эхом без объяснений.

Сохранение применяется сразу, без перезапуска — можно тут же
возвращаться в чат. Диалог помнит контекст в рамках сессии (кнопка
«🔄 Новый чат» сбрасывает историю), так что если задача сформулирована
нечётко, агент (при реальном LLM-провайдере) задаст уточняющий вопрос
вместо того, чтобы действовать наугад — это часть системного промпта
по умолчанию.

## Диагностика: проверка связи и журнал ошибок

Статус «Сейчас отвечает: …» на вкладке **Настройки** показывает, какой
провайдер выбран, но не то, отвечает ли он на самом деле (неверный
ключ, недоступный API, битый файл модели видны иначе только при первом
реальном сообщении в чате). Рядом с этой строкой — кнопка **«🔌
Проверить подключение»**: отправляет короткий тестовый запрос прямо
сейчас и показывает ✅ с ответом провайдера либо ❌ с текстом ошибки.
Аналогичная кнопка **«🔌 Проверить связь с Hugging Face»** есть на
вкладке **Модели** — обращается к Hub тем же способом, что и поиск
моделей, и сразу показывает, работает ли сеть до huggingface.co
(включая случаи, когда нужна авторизация или доступ заблокирован
файрволом/прокси).

Все сбои навыков (в т.ч. поиск/скачивание с Hugging Face) и ошибки
обращения к LLM-провайдеру пишутся с полным traceback'ом в файл журнала
`~/.ai-agent/agent.log` — путь к нему и кнопка **«📄 Открыть журнал»**
есть на вкладке **Права доступа**. Если что-то не работает и сообщение
об ошибке в интерфейсе недостаточно подробное — этот файл содержит
реальную причину (текст исключения на месте, где оно возникло) и его
можно приложить при сообщении о проблеме. Значения, похожие на токены/
ключи/пароли, в журнал не пишутся (заменяются на `***`).

## Модели с Hugging Face

Вкладка **Модели** при открытии сама определяет характеристики ПК (CPU,
RAM, GPU) и показывает из курируемого списка только те модели, которые
реально поместятся в память — с запасом, а не впритык. Там же — поиск
любых моделей на Hugging Face Hub по названию и кнопка скачивания.

Сама рекомендация не требует ни сети, ни разрешений — это локальный
расчёт по железу. Поиск использует обычное сетевое разрешение
(`network.enabled`). А вот **скачивание** — отдельная политика
(`model_download.enabled`, по умолчанию `false`) с обязательным
подтверждением на каждую модель, потому что это гигабайты трафика и
диска: агент не может незаметно утащить несколько моделей себе на
жёсткий диск.

**Скачивание выключено по умолчанию** — прежде чем кнопка «⬇ Скачать»
заработает, включите галочку **«Разрешить скачивание моделей с Hugging
Face»** прямо на вкладке (сохраняется в `policy.yaml` сразу, без
перезапуска приложения).

### Если модель не скачивается: авторизация

Часть моделей на Hugging Face закрыта политикой доступа ("gated") —
например `meta-llama/Llama-3.1-8B-Instruct` из рекомендаций: чтобы её
скачать, нужен аккаунт на Hugging Face, принятая лицензия и
access-токен. Без токена такое скачивание (и иногда поиск) завершится
ошибкой — это выглядит как «просто не скачивается».

На вкладке **Модели** есть раздел **«Авторизация Hugging Face»**:

1. Кнопка **«🔗 Открыть страницу авторизации»** открывает в браузере
   `https://huggingface.co/settings/tokens` — там создаётся токен
   (Access Token) после входа в аккаунт.
2. Токен вставляется в поле рядом и сохраняется кнопкой **«💾
   Сохранить»** — приложение сразу проверяет его (запрос `whoami`) и
   сохраняет в собственный локальный кеш `huggingface_hub`
   (`~/.cache/huggingface/token` — Windows: аналогично в
   `%USERPROFILE%`), после чего все последующие запросы к Hugging Face
   используют его автоматически.
3. Для gated-моделей (как Llama 3.1) отдельно нужно принять лицензию
   на странице самой модели на huggingface.co — простого наличия
   токена не всегда достаточно.

Если ошибка скачивания/поиска вызвана именно нехваткой авторизации,
статус под кнопками прямо на это укажет и подскажет открыть страницу
токенов. Если ошибка сетевая (нет интернета, файрвол/прокси блокирует
huggingface.co) — текст ошибки будет об этом, не об авторизации.

По умолчанию отключён ускоренный бэкенд скачивания Hugging Face
("Xet") — на части сетей (корпоративные фаерволы, некоторые антивирусы)
он обрывается на больших файлах, при этом мелкие служебные файлы
репозитория успевают скачаться, и в `workspace/models/` остаётся папка
с моделью размером «~0.0 ГБ» вместо реальных весов. Обычный HTTPS
медленнее, зато проходит почти везде. Такие пустые папки-призраки от
неудачных попыток теперь и сами удаляются автоматически.

### Если через приложение так и не скачивается: импорт вручную

Скачанные через приложение файлы кладутся в `workspace/models/` — эта
папка создаётся сразу при первом запуске (даже без единого скачивания).
Если скачивание через Hugging Face всё равно не работает (сеть,
файрвол, VPN и т.п.) — на вкладке **Модели**, в разделе «Локальные
модели», есть кнопки **«📄 Импортировать файл…»** и **«📁
Импортировать папку…»**: скачайте модель любым другим способом (браузер,
менеджер закачек, `git clone` репозитория модели) и укажите путь к
файлу/папке — приложение скопирует её в `workspace/models/`. Это то же
самое, что просто скопировать файл в папку через проводник, но с
навигацией из самого приложения. Раздел «Локальные модели» (кнопка «🔄
Обновить») показывает всё, что там лежит — и то, что скачал агент, и
то, что добавили вы, любым способом.

То же самое доступно агенту как обычные навыки в чате:
`models.recommend`, `models.search_huggingface`,
`models.download_huggingface`, `models.list_local`,
`models.import_local`, `models.set_hf_token`,
`models.clear_hf_token` — можно попросить словами: "подбери модель под
мой ПК", "скачай Qwen2.5 1.5B" или "добавь модель из C:\Downloads\model.gguf".

## Где хранятся данные

- `~/.ai-agent/` — конфиги (`policy.yaml`, `settings.yaml`), память
  (`memory.sqlite3`), журнал аудита (`audit.jsonl`), журнал ошибок и
  диагностики (`agent.log`, см. раздел «Диагностика» выше). Сам агент не
  имеет доступа к этой папке через свои навыки.
- `~/AiAgentWorkspace/` — рабочая песочница агента: файлы, `documents/`
  (созданные Word/PowerPoint/PDF/Excel), `scripts/` (написанные им самим
  вспомогательные скрипты), `models/` (модели — скачанные с Hugging Face
  или добавленные вручную, см. раздел выше).

Пути переопределяются флагами `--state-dir` / `--workspace` у CLI или
параметрами `MainWindow(state_dir=..., workspace_root=...)` у GUI.

## Права доступа и запреты

Всё небезопасное по умолчанию выключено: `~/.ai-agent/policy.yaml`
(создаётся из [`config/policy.default.yaml`](config/policy.default.yaml)
при первом запуске):

- `shell.enabled: false` — агент не может выполнять системные команды.
- `scripting.execute_enabled: false` — писать скрипты может, запускать — нет.
- `package_install.enabled: false` — не может ставить новые пакеты.
- `model_download.enabled: false` — не может скачивать модели с Hugging Face.
- `workspace_only: true` — файлы только внутри рабочей папки.

Включите нужное и перезапустите приложение. Действия из
`confirmation_required_for` дополнительно спрашивают подтверждение в
момент выполнения (в CLI — вопрос в терминале, в GUI — диалоговое окно).

## Сборка в .exe (Windows)

PyInstaller не кросс-компилирует, поэтому сборка запускается **на
Windows** — локально или автоматически в CI.

### Автоматически (рекомендуется)

Workflow [`.github/workflows/build-windows-exe.yml`](.github/workflows/build-windows-exe.yml)
собирает `.exe` на `windows-latest` при каждом пуше и кладёт его в
Artifacts запуска (`AI-Agent-windows`) — скачать можно со страницы
Actions в GitHub без своей Windows-машины.

### Локально на Windows

```powershell
pip install -e ".[all]"
pip install pyinstaller
pyinstaller packaging\build.spec --noconfirm
```

Результат: `dist\AI-Agent\AI-Agent.exe` (папка `dist\AI-Agent\` — режим
"onedir": быстрее стартует и реже ложно триггерит антивирусы, чем
однофайловая сборка).

Сборка подтверждена дважды: локально здесь через `pyinstaller` для
Linux-бинарника (кросс-платформенная логика spec-файла и
bootstrap-кода одинакова — приложение стартует, создаёт `~/.ai-agent` и
`~/AiAgentWorkspace`, автоопределяет профиль производительности), и что
важнее — **на настоящем `windows-latest`** в CI: полный прогон тестов и
сборка `.exe` завершаются зелёным (см. Actions).

## Известные ограничения MVP

- Установка новых Python-пакетов (`skills.install_package`) ставит их в
  то же окружение, где работает агент, а не в изолированный venv —
  риск компенсируется тем, что это выключено по умолчанию и требует
  подтверждения на каждый пакет.
- Поиск в интернете (`web.search`) парсит HTML-выдачу DuckDuckGo без
  API-ключа — это MVP-решение; в проде разумнее подключить платный
  Search API.
- "Самообучение" — это память + retrieval прошлых эпизодов, а не
  дообучение весов модели (см. обоснование в `PLAN.md`, раздел 8).
- Локальный LLM-провайдер (`llama-cpp-python`) не проверен здесь на
  реальном инференсе: юнит-тесты используют подставной клиент (в
  песочнице сборки нет ни компилятора под этот пакет "из коробки", ни
  сетевого доступа к настоящей GGUF-модели). Код и текстовый протокол
  вызова инструментов реализованы по документированному API пакета, но
  качество и соблюдение формата на конкретной скачанной модели стоит
  проверить самостоятельно.
- История диалога в чате не обрезается и не суммаризируется — при
  очень долгой сессии можно упереться в лимит контекста провайдера.
  Кнопка «Новый чат» — текущий способ начать с чистого листа.
